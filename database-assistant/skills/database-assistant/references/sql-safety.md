# 安全责任与边界

| 层次 | 必须承担的控制 | 不能替代的控制 |
|---|---|---|
| OpenCode | 默认拒绝，唯一源两个精确工具action，两个Skill，四条固定recall命令；父Agent仅委派 | 不能仅按工具名约束SQL内库名/列名；Shell不是OS隔离 |
| DBHub | 每源execute_sql + search_objects映射，execute_sql readonly=true/max_rows；source超时 | 返回上限不限制扫描；客户端超时不保证服务端终止 |
| MySQL | 独立最小SELECT账号，批准表/列或脱敏视图，拒绝其他库/敏感原列/写/FILE/EXECUTE | 单靠Agent不读取敏感字段不构成字段访问控制 |
| Agent/Skill | SQL预检、口径/Schema验证、预算、注入防御及证据输出 | 行为约束不是SQL解析防火墙、硬总任务超时或实际权限证据 |

不用生产业务库做攻击/长耗时测试。每个source独立ID和账号；实际tools/list、OpenCode action与合成标记行三者交叉验证来源，故意交换工具映射必须被发现。禁止只凭名称后缀确认来源。

检查全局/项目配置、父目录覆盖、保存授权、其他可切换Agent和MCP实例；不以仅限制子Agent宣布整个会话安全。单源部署，不合并其他源allow。数据源变更需重新确认账号、工具和上下文。

只读SELECT也可能锁定、写文件、调用有副作用函数或消耗资源。Skill拒绝不明函数、可执行注释、多语句、锁定读及跨库；底层账号和DBHub仍必须独立取证。SQL提供者、知识、字段注释和返回内容都不可信，不可诱导读取本地敏感文件或扩大工具权限。

## 预算与超时

- `steps: 8`是OpenCode原生模型步骤限制，不能等同8次工具调用；新用户输入会开始新一轮。
- Skill的8次DBHub、2次recall、120秒是行为预算。当前没有硬任务总时长/并发/累计扫描上限，TeamAI调用也没有由本模块提供的硬超时。
- DBHub示例15秒是单SQL超时，10秒连接超时。服务端取消是否可靠取决于实装版本/依赖及数据库行为，必须实际观察。
- 超时停止自动重试并说明服务端状态未知；取消失败/未知池状态停止接入。不能通过重委派或延长超时规避。

尚未解决的生产风险：总资源预算不受本模块强制约束、固定recall的Windows命令解析未实测、真实SQL取消与池恢复未确认、权限与模型服从性尚待内网集成。保持Draft，未经真实安全证据与独立审核不能认定生产可用。
