## 问题明细

### F-001 · 高 · 审批更新缺少商户隔离条件

**问题与触发条件**

本示例中，入口使用请求中的订单 ID 更新状态，已检查的业务方法没有订单归属校验；更新 SQL 只按订单 ID 定位。当调用方提交其他商户的有效订单 ID 时，存在跨商户更新风险。

**业务影响**

可能破坏商户间数据隔离，使订单被非所属商户审批。实际可利用性仍需结合部署中的身份与权限配置验证。

**代码位置**

`src/main/resources/mapper/OrderMapper.xml`，`updateStatus`，示例第 18–21 行。

**关键证据（示例）**

```sql
UPDATE orders
SET status = #{status}
WHERE id = #{orderId}
```

业务方法与入口的归属校验缺失证据在正式报告中必须同时引用，不能仅凭以上 SQL 片段断言整个系统无隔离措施。

**修复建议**

从可信登录上下文获取商户身份，在业务校验及更新条件中绑定订单归属；检查更新行数并明确失败语义。

**验证建议**

- 当前商户审批自己的订单成功。
- 当前商户审批其他商户订单被拒绝，数据库状态不变。
- 不存在的订单 ID 不被误报为审批成功。
