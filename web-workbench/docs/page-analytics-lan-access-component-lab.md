# 智能工作台：页面统计、局域网协作、统一权限、组件测试（PR #115）

## 单一工作台入口
Windows 用 `启动工作台.cmd "D:\\teamai"`，Mac 用 `./启动工作台.command "/Users/用户名/teamai"`。工作目录是唯一必填参数，其余选项由 **Windows/Mac 共用的交互菜单**选择：

1. 访问方式：仅本机（默认）、局域网、沿用现有环境变量
2. 局域网 IP：仅选择局域网时，从可用的私有 IPv4 网卡列表选择
3. **服务端口：默认/当前端口 4176（可被预设环境变量覆盖），快捷 4177、8080，或选择自定义并输入 1024–65535**
4. 机构页 Shell：受限（默认）、开放 Shell + 文件读写
5. LAN + Shell 全开放时需额外风险确认

自定义端口会同时更新服务监听端口、`HARNESS_PUBLIC_ORIGIN` 和 `HARNESS_EMBED_PARENTS`，保证浏览器访问、登录校验和嵌入页面使用一致端口。若端口已被占用或不可绑定，启动前会给出明确错误。Mac 在服务就绪后自动打开实际端口的本机页面；脚本化/CI 启动不弹交互菜单，继续沿用原有环境变量。

示例：端口选择 5188 后，配置页为 `http://127.0.0.1:5188/config`，局域网 IP 为 `192.168.1.66` 时，同事访问 `http://192.168.1.66:5188/`。

启用 LAN 后，**不再生成或要求局域网访问码**，也不再使用旧环境变量 `HARNESS_LAN_ACCESS_CODE`。把电脑的局域网 IP 和端口发给同事即可；每位同事在普通业务页面输入自己的姓名和手机号后进入工作台，浏览器获得独立 Cookie 和 OpenCode Session 归属。**姓名、手机号只是自报资料，不是身份认证。任何能够连接该端口的人都能登录并调用获准开放的业务场景。** 因此必须通过 Windows 防火墙限制来源 IP、仅开放可信企业内网，不要映射公网端口；涉及敏感数据或高权限 Shell 时应使用公司的认证网关和 HTTPS。

可以直接打开：
- 工作台主页：`http://<本机局域网IP>:4176/`
- 机构报文排查：`http://<本机局域网IP>:4176/embed/institution-message`
**以下三项只能从启动机器本机访问，不向局域网开放：**
- 场景配置：`http://127.0.0.1:4176/config`
- 公共组件测试：`http://127.0.0.1:4176/component-lab`
- 访问统计：`http://127.0.0.1:4176/analytics`

以上地址中的 `4176` 都应替换为实际启动菜单选择的端口。

公管问题排查、普通报文排查、公管数据分析和代码审查仍由主工作台侧栏进入。主工作台和配置页共用原始启动工作目录，不新增第二套 OpenCode、MySQL 或服务端口。

**固定局域网边界**：`/config`、`/component-lab`、`/analytics` 和统计数据读取 API `GET /api/v1/page-visits` 均要求真实环回 IP + 本机 Host。即使老版本权限文件曾将测试/统计页面设为 `lan:true`，服务器仍拒绝远程访问。配置修改继续要求管理员与 CSRF。`POST /api/v1/page-visits` 仍允许其他业务页面上报访问量，不向同事暴露统计明细。局域网用户侧栏不展示上述三个页面入口。

## 访问统计

仅在启动机器本机的工作台侧栏点击「访问统计」，或从本机打开 **`http://127.0.0.1:<端口>/analytics` 独立页面**，查看最近 7 天或 30 天的 PV、UV、按天趋势、最近访问时间。页面不嵌在 `/config`，但属于管理页面，**不对局域网同事开放**。由浏览器页面加载/导航产生统计请求，双重挂载和两秒内快速重复访问会合并；访问日志最多保留 90 天。数据库默认保存于系统账号私有的 `.smart-workbench/state/page-visits.sqlite`，独立于业务工作目录，升级及进程重启可继续统计。

统计只持久化页面编码、访问时间、随机页面运行实例标识的 SHA-256 摘要，不保存 IP、姓名、手机号、报文编号或执行内容。访客标识仅存内存，尤其不向匿名 iframe 的 LocalStorage/SessionStorage 写入追踪值。UV 按当前页面运行实例去重，刷新页面通常会重新计为访客，不等同于企业实名认证人数。

## 页面权限统一配置

在 `/config` 下的「各页面权限管理」选择场景，再配置细粒度权限。文件继续保存在工作目录 `.workbench/scene-access.json`，不覆盖已有 `.workbench/scenarios.json`。权限文件升级为 **version 2**，旧版 version 1 会在读取时兼容迁移，首次保存后写入新结构。

- 局域网访问：对话首页、代码审查、公管问题排查、报文问题排查、机构报文排查、公管数据分析等业务页面默认支持局域网访问，可逐场景关闭。配置、组件测试、访问统计属于仅本机页面，不提供远程访问开关；旧配置中的开放值会自动收敛为关闭。
- **命令与 Agent**：Shell、Code Mode (`execute`)、Skill、Subagent
- **文件与目录**：read、write、edit、glob、grep、list、external_directory
- **联网工具**：webfetch、websearch（已安装对应工具时才实际生效）
- **DBHub MCP**：dbhub_search_objects、dbhub_execute_sql
- **其他 MCP / 工具**：可输入实际 `action` 名称、`resource` 匹配资源，以及允许／询问／拒绝；每个场景最多 16 条

每项原生工具可选「继承默认 / 允许 / 每次询问 / 拒绝」。对应 OpenCode 原生权限规则以 `action + resource + effect` 下发，只有安装且受 OpenCode 识别的 action 才会实际起作用；并非自动安装或配置新工具。代码审查仍是独立 Review 调度器，因此这里仅控制其页面 LAN 权限，暂不声称控制其独立执行器的 Shell 规则。

权限在**服务端**为 OpenCode 新 Session 生效，原生会话的权限回显仍要核验。若旧 Session 配置已不一致，会拒绝后续使用并要求创建新 Session；不能靠前端 UI 按钮隐藏替代权限控制。原生 Shell 的允许权限可以绕过独立的文件写入禁止开关，因而这些选项不是操作系统沙箱。其他名称的 MCP 权限仍遵循 OpenCode 配置，不代表任意 MCP 已被封禁。

机构匿名页在原有基础权限与 `HARNESS_INSTITUTION_ALLOW_SHELL` 启动选项之上叠加统一配置；命令行开关和配置页的「允许」均会放宽匿名机构 Shell，务必配合可验证身份、最小 Windows 账号权限及 LAN 白名单使用。现有独立 Shell/DBHub 业务功能不做替换。

## 组件测试页

`/component-lab` 仅用于 UI 交互验证，不会向业务系统查询或向模型发送提示词。包括原生日期控件、秒级时间输入、一天的时区 / 夏令时边界预览、模拟模型选择器、按钮、弹窗、基础表单以及验证提示。日志问题排查和机构报文排查实际使用同一套 `TimeFields.tsx` 公共日期组件。

## 验收建议

先用本机 `/config` 保存 Shell 和 LAN 场景策略，再由至少两个同事分别从局域网 IP 访问，确认互相无法查看/中断对方的 Session。**必须验证远程 `/config`、`/component-lab`、`/analytics` 及统计 GET API 均返回 403，本机这三个页面均可访问。** 在本机打开 `/analytics` 验证 7/30 日切换，确认业务页面 LAN 访问成功；验证组件测试页日期与秒级时间输入，机构页日期和旧业务排查功能仍可用；确认 PV/UV 在刷新、切换场景、重启后稳定并且不会因 React StrictMode 重复统计。

真实内网权限效果、团队网络防火墙、HTTPS 网关和私有模型 / DBHub 仍须在企业内网验证，自动化 CI 不能替代真实数据与工具调用测试。

## 会话隔离修复（本机账户切换与 LAN 多人访问）

- 后端本机登录原本用固定的 `local-workbench` 作为所有账号的 OpenCode Owner，现改为基于**当前工作目录用户资料**的稳定 `local:<profile-key>`。同一资料再次登录可找回自己的新会话，不同资料不会共享 Owner。
- LAN 模式继续为**每次独立浏览器登录**分配不同的 `lan:<UUID>` Owner；姓名手机号相同也不会自动继承上一次 Cookie 的聊天记录。用户资料是自报信息，不等于身份认证。
- 浏览器 `localStorage/sessionStorage` 统一使用 `harness.user.<ownerId>.` 前缀，包含 localhost 登录。旧版本未经分区的浏览器缓存**不自动迁移**，以免将前一位用户的标题、草稿或会话 ID 错误分配给新人。
- 侧栏「最近对话」和「历史对话」只展示服务端根据当前认证会话的 `harnessOwner` 返回的会话；浏览器缓存只可补充已确认属主的标题。读取、追问、重命名、删除、中断及 SSE 订阅都在服务端核对 session Owner。
- **升级注意**：升级之前创建的 localhost OpenCode Session 使用无法区分用户的旧 `local-workbench` 标记。为了防止历史会话跨用户泄露，这部分数据会被**保留在原生服务中但不自动展示/认领**。如需合规导出，必须由本机管理员先核实其真实归属，不能批量划给一个登录用户。
- **尚无强认证**：已按要求取消 LAN 共享访问码；目前只是不同浏览器会话与自报资料的隔离。如果要防止同事冒充另一个人的姓名/手机号并安全恢复其历史，应接企业 SSO、网关身份校验或其他可验证的用户凭证。也应通过防火墙只允许受信任的来源 IP。
- 验收时按用户 A 创建会话、退出、切换 B、检查空列表及旧 sessionId 访问得到 404、B 创建会话、A 再次登录只看到 A 的新会话；并使用两台不同 LAN 浏览器验证不会交叉显示。不得使用旧版包验收。

## 机构任务分页与登录审计（2026-11-25）

- **任务列表**：原接口虽有 SQL `LIMIT 50 OFFSET`，现增加 `limit=20|50|100` 可选参数，并保留缺省 `50` 供旧 B/C 管理客户端使用。管理员任务页新增总页数、每页条数和页码跳转；业务用户聚合及其嵌套任务列表也采用服务器端分页。搜索或改变页大小时返回第一页，删除/过期造成空页时回退至最后有效页。任务执行/并发调度不变。
- **时间编辑**：自定义排查时间范围和机构报文的「调整日期」使用渐进式 `YYYY-MM-DD` 文本输入，以避免部分 Windows 原生日期控件在按 Delete/Backspace 编辑单个字段时发送临时空值、导致日期整体变空。日期不完整时禁止重新排查；取消调整后恢复此前已应用条件，当前会话已有聊天结果不受影响。整日选择器仍保留原生日历。
- **登录记录**：成功登录时写入独立的 `user_access_log`，记录登记姓名、脱敏手机号、来源 IP、Local/LAN、登录时间、最近 API 活动和退出时间。使用每次登录 Cookie 的随机 auditId 做记录索引，不记录 Session Cookie 原文、手机号原文、报文正文或聊天内容。关闭浏览器/网络中断没有可靠的退出事件，故显示「未记录退出」，**不得推断当前在线**。
- **访问入口**：工作台本机的「系统管理 → 用户访问记录」或 `http://127.0.0.1:4176/analytics?view=users`。`GET /api/v1/user-visits?days=7|30&offset=0&q=` 仅允许实际回环请求 + 本机已登录配置管理员（`.workbench/config-access.json` 的 editors），非管理员、LAN 同事和外部系统不能访问；分页大小 20。
- **数据存储**：与 PV/UV 共用 %LOCALAPPDATA% 下 `.smart-workbench/state/page-visits.sqlite`，审计记录最多保留 90 天。只对升级后发生的登录/访问建立记录；不能倒推出此前哪些同事登录过。姓名和手机号由本人填写，未接企业 SSO，因此记录仅供操作追溯，不代表强身份认证。
